# Quy trình Deploy Gộp — Tháng 11/2026 (`DEPLOY-2026-11`)

Tài liệu một trang quy định **thứ tự bắt buộc** cho đợt deploy gộp lên production (`main` + `fix/payments-safety`). Thực hiện tuần tự từng bước, không đảo thứ tự.

| Thành phần | Nơi thực hiện | Ghi chú |
| --- | --- | --- |
| Biến môi trường, Build/Deploy container, Xem log, Rollback ứng dụng | **Coolify** | Resource Backend (`dvid-api.vibe1.tinhgon.xyz`) & Frontend (`dowloadvideo.io.vn`) |
| Migration `044`, `045`, Kiểm tra bảng/RLS & đối soát dữ liệu | **Supabase** | Supabase Dashboard → SQL Editor (hoặc `psql "$SUPABASE_DB_URL"`) |
| Merge nhánh vào `main` | **Git (Local / GitHub)** | Chỉ thực hiện sau khi hoàn tất Bước 1 → Bước 3 |

## Bước 1 — Kiểm tra & đặt biến môi trường cần có (**trên Coolify**)

1. **Trên Coolify → Resource `Backend` → Environment Variables**:
   - `ENV=production`
   - `FLOW_URL_SIGNING_SECRET`: chuỗi hex ngẫu nhiên tối thiểu 32 ký tự (tạo bằng `openssl rand -hex 32`). **Bắt buộc có trước khi deploy** (thiếu hoặc `< 16` ký tự thì `backend` dừng khởi động ngay tại `_validate_signing_secret_on_startup()`) và **không dùng trùng** với `JWT_SECRET` hay `SUPABASE_SERVICE_KEY`.
   - `REDIS_URL`: chuỗi kết nối Redis đang dùng cho Celery, session Admin, `plans:settings` và quota `flow:*`.
   - `SUPABASE_URL`, `SUPABASE_KEY`, `SUPABASE_SERVICE_KEY`: đảm bảo `SUPABASE_SERVICE_KEY` là `service_role` key (bảng `payment_webhook_events` chỉ cho phép `service_role` đọc/ghi qua RLS).
   - `ADMIN_PASSWORD`: mật khẩu đăng nhập `/vid-admin` (xem & xử lý danh sách `needs_manual_review`).
   - `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`: kênh Telegram nhận cảnh báo tự động mỗi khi có giao dịch `needs_manual_review`.
   - Biến các cổng thanh toán đang mở:
     - **SePay / VietQR**: `SEPAY_WEBHOOK_SECRET` (kèm thông tin TK ngân hàng trong `plans:settings` hoặc `BANK_BIN`).
     - **PayPal**: `PAYPAL_CLIENT_ID`, `PAYPAL_CLIENT_SECRET`, `PAYPAL_WEBHOOK_ID` (hoặc `PAYPAL_ME_URL`, `PAYPAL_MODE=live`).
     - **Stripe** *(nếu bật)*: `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, và các `STRIPE_*_PRICE_ID` tương ứng gói đang bán.
   - *Lưu ý build pack trên Coolify*: nếu Resource Backend dùng `Dockerfile` (`backend/Dockerfile`), mọi biến trên Coolify được truyền thẳng vào container. Nếu dùng `Docker Compose` (`docker-compose.yml`), cần khai báo thêm `FLOW_URL_SIGNING_SECRET=${FLOW_URL_SIGNING_SECRET}` trong phần `environment` của service trên Coolify.
2. **Trên Coolify → Resource `Frontend` → Environment Variables (Build-time & Runtime)**:
   - Kiểm tra **KHÔNG** có `VITE_FEATURE_LOGO_INPAINT=true` hoặc `VITE_FEATURE_LOGO_INPAINT=1` (bỏ trống hoặc đặt `VITE_FEATURE_LOGO_INPAINT=false` để giữ khoá lối tắt xoá-logo trên giao diện).

## Bước 2 — Chạy Migration `044` (**trên Supabase**)

Mở **Supabase Dashboard → SQL Editor** (hoặc dùng `psql "$SUPABASE_DB_URL"`), chạy nguyên văn file `database/migrations/044_flow_consent_audit_logs.sql`.

Kiểm tra ngay trên **Supabase SQL Editor**:
```sql
SELECT tablename, policyname, roles, cmd
FROM pg_policies
WHERE tablename = 'flow_consent_audit_logs';
```
- **Kỳ vọng**: có policy `flow_consent_audit_logs_own` trên bảng `flow_consent_audit_logs` (cùng 2 index `idx_flow_consent_audit_logs_user_created`, `idx_flow_consent_audit_logs_temp_id`).

## Bước 3 — Chạy Migration `045` (**trên Supabase**)

Tiếp tục trên **Supabase Dashboard → SQL Editor**, chạy nguyên văn file `database/migrations/045_payment_webhook_events.sql` (**bắt buộc chạy xong trước khi deploy code**).

Kiểm tra bảng, 3 index và RLS trên **Supabase SQL Editor**:
```sql
SELECT indexname FROM pg_indexes WHERE tablename = 'payment_webhook_events' ORDER BY indexname;
SELECT tablename, policyname, roles, cmd FROM pg_policies WHERE tablename = 'payment_webhook_events';
```
- **Kỳ vọng**:
  - Có đủ 3 index: `idx_payment_webhook_events_provider_event`, `idx_payment_webhook_events_status`, `idx_payment_webhook_events_user` (cùng primary key `payment_webhook_events_pkey`).
  - Có policy `payment_webhook_events_service_role_only` với `roles = {service_role}`, `cmd = ALL`.

## Bước 5 — Deploy ứng dụng (**trên Coolify**)

1. **Deploy `Backend` trước** trên Coolify:
   - Mở Resource `Backend` → bấm **Deploy** → theo dõi Deployment Logs đến khi container `Running (healthy)`.
   - Mở Logs của `Backend`, xác nhận:
     - Không có `RuntimeError: FLOW_URL_SIGNING_SECRET is required in production`.
     - Có đủ 2 Celery worker (`downloads,bulk,media,analysis` và `partner,light,celery`) cùng `uvicorn` trong `docker-entrypoint.sh`.
   - Kiểm tra healthcheck: `curl -fsS https://dvid-api.vibe1.tinhgon.xyz/health` → trả `HTTP 200`.
   - *(Tuỳ chọn chỉ đọc trên Coolify Terminal)* kiểm tra giá đang lưu trong Redis (không xoá):
     `redis-cli -u "$REDIS_URL" GET plans:settings`
2. **Deploy `Frontend` tiếp theo** trên Coolify:
   - Mở Resource `Frontend` → bấm **Deploy** → chờ Vite build + prerender hoàn tất và container chạy ổn định.

## Bước 7 — Cách Rollback khi có sự cố (**Coolify vs Supabase**)

1. **Trên Coolify (Rollback ứng dụng — ưu tiên thực hiện trước, mất ~1–2 phút)**:
   - Vào Resource `Backend` → tab **Deployments** → tìm bản deploy xanh liền trước đợt merge (ví dụ commit `49edf1e`) → bấm **Redeploy** (hoặc đặt `Commit SHA` về `49edf1e` trong mục General rồi bấm **Deploy**).
   - Làm tương tự cho Resource `Frontend` trong tab **Deployments** nếu giao diện phát sinh lỗi.
   - Nếu có phiên xoá-logo bị ngắt giữa chừng giữ khoá trên Redis, mở **Coolify → Backend Terminal** xoá khoá tạm (chỉ xoá `flow:active_job:*`, không chạm các key khác):
     ```bash
     redis-cli -u "$REDIS_URL" --scan --pattern "flow:active_job:*" | xargs -r redis-cli -u "$REDIS_URL" DEL
     ```
2. **Trên Supabase (Giữ nguyên dữ liệu đối soát)**:
   - **KHÔNG DROP** hai bảng `flow_consent_audit_logs` (Migration `044`) và `payment_webhook_events` (Migration `045`). Cả hai bảng hoàn toàn độc lập, không gắn trigger hay khoá ngoại làm ảnh hưởng code cũ, và cần giữ lại toàn bộ bản ghi `needs_manual_review` để đối soát/hoàn tiền cho khách.
   - Nếu trong lúc smoke test có tài khoản bị nâng nhầm gói cần trả về trạng thái cũ, chỉnh trực tiếp `tier`, `billing_status`, `subscription_expiry` của đúng `user_id` đó trong bảng `profiles` và `plan` trong `user_usage` trên **Supabase Table Editor** (hoặc qua `/vid-admin`).
